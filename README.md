# סופר דיירקט

אתר סופר מקוון להזמנת מוצרים, ניהול סל והזמנות, ולניהול מוצרים וקטגוריות.
הפרויקט כולל ממשק לקוח, שרת API ומסד נתונים MongoDB Atlas.

## תכונות עיקריות

- הרשמה, התחברות וניהול פרופיל לקוח.
- תפקידים והרשאות: לקוח ומנהל. פעולות ניהול מוגנות גם בצד השרת.
- צפייה במוצרים ובקטגוריות, וסל קניות והזמנות.
- ממשקי ניהול למוצרים, קטגוריות, משתמשים, הזמנות והודעות.
- פעולות CRUD למוצרים ולקטגוריות.
- אימות נתונים בצד השרת באמצעות Joi ובדיקות בטפסים בצד הלקוח.
- תמיכה בתמונות מוצר וקטגוריה, תמונות מצורפות להודעות, וסרטון תדמית עם פס קול.
- ממשק רספונסיבי וכלי נגישות.

## טכנולוגיות

- צד לקוח: HTML, CSS ו־JavaScript.
- צד שרת: Node.js ו־Express.
- מסד נתונים: MongoDB עם Mongoose, המיועד להתחברות ל־MongoDB Atlas.
- אימות והרשאות: JWT, הצפנת סיסמאות עם bcrypt ובדיקת תפקידים.
- העלאת תמונות: Multer.

## מבנה הפרויקט

```text
client/     עמודי האתר, קובצי CSS, JavaScript, תמונות וסרטון
server/     שרת Express, API, מודלים, סכמות וסקריפטים
docs/       תיעוד API ואוסף בקשות Postman
```

השרת מגיש גם את ממשק האתר מתוך `client`, לכן בהרצה המקומית אין צורך להפעיל שרת נפרד לצד הלקוח.

## דרישות מקדימות

- Node.js ו־npm.
- מסד נתונים זמין ב־MongoDB Atlas.
- משתמש Atlas עם הרשאות למסד וכתובת השרת מורשית ב־Network Access של Atlas.

## התקנה והרצה מקומית

1. שכפלו את המאגר והיכנסו לתיקיית השרת:

   ```powershell
   git clone https://github.com/shaked620d-hue/Super_Direct.git
   cd Super_Direct/server
   npm install
   ```

2. צרו בתיקיית השרת קובץ `.env` ובו הגדירו את המשתנים הבאים:

   ```dotenv
   PORT=5000
   MONGODB_URI=<MongoDB Atlas connection string>
   JWT_SECRET=<long-random-secret>
   ADMIN_EMAIL=<administrator-email>
   ADMIN_PASSWORD=<strong-administrator-password>
   ```

   יש להחליף את ערכי הדוגמה בערכים שלכם. אין לשמור סיסמאות, מפתחות או מחרוזת חיבור אמיתית בקובץ README או במאגר Git.

3. הפעילו את השרת:

   ```powershell
   npm start
   ```

4. פתחו בדפדפן את [http://localhost:5000](http://localhost:5000).

השרת טוען את ההגדרות מתוך `server/.env`. אם החיבור למסד הנתונים נכשל, בדקו את כתובת Atlas, פרטי המשתמש והרשאות הרשת, וחפשו במסוף את הודעת השגיאה.

## נתוני התחלה

לאחר הגדרת `.env`:

- ליצירת משתמש מנהל לפי `ADMIN_EMAIL` ו־`ADMIN_PASSWORD`:

  ```powershell
  node scripts/seedAdmin.js
  ```

- ליצירה או לעדכון של קטגוריות ברירת מחדל:

  ```powershell
  npm run seed:categories
  ```

לקוחות יכולים להירשם דרך האתר. סקריפט המנהל יוצר חשבון בתפקיד `admin`; חשבון רגיל נוצר בתפקיד `customer`.

## API

כל נתיבי ה־API מתחילים ב־`/api`:

| תחום | נתיב בסיס | שימוש |
|---|---|---|
| אימות | `/api/auth` | הרשמה, התחברות, משתמש נוכחי ושינוי סיסמה |
| מוצרים | `/api/product` | צפייה וניהול מוצרים |
| קטגוריות | `/api/category` | צפייה וניהול קטגוריות |
| משתמשים | `/api/user` | צפייה וניהול משתמשים |
| הזמנות | `/api/order` | יצירה, צפייה ועדכון הזמנות |
| הודעות | `/api/message` | שליחת הודעות וניהולן |

פעולות ניהול דורשות משתמש מנהל מאומת. פעולות לקוח מוגבלות למידע ולהזמנות שלו, בהתאם לנתיב.

## פריסה בענן

הפרויקט כולל שרת Express שמגיש באותו מקור גם את ה־API וגם את קובצי האתר. בעת פריסה של השרת יש להגדיר בסביבת האירוח את משתני הסביבה `PORT`, `MONGODB_URI`, `JWT_SECRET`, `ADMIN_EMAIL` ו־`ADMIN_PASSWORD`; אין להעלות את `.env` לענן דרך Git. יש להגדיר ב־Atlas הרשאת רשת עבור סביבת האירוח ולוודא שהשרת מצליח להתחבר למסד.

תמונות שמועלות דרך האתר נשמרות כרגע תחת `server/public`. לפני שימוש באחסון ענן יש לוודא שלסביבת האירוח יש אחסון קבצים מתמשך, או להעביר את התמונות לשירות אחסון מדיה מתאים; מערכת קבצים זמנית עלולה להימחק בפריסה מחדש.

## עבודה עם Git

מומלץ שכל אחד מחברי הצוות יעבוד עם חשבון GitHub שלו, ישמור שינויים ב־commits תיאוריים, ויסנכרן את העבודה דרך המאגר המשותף ובדיקת שינויים לפני מיזוג.

## אבטחת מידע

- הקובץ `server/.env` מוחרג מ־Git. אין לפרסם בו או בקוד סודות אמיתיים.
- החליפו את `JWT_SECRET` בערך אקראי וחזק בסביבות פיתוח ופריסה.
- השתמשו בסיסמת מנהל חזקה, ואל תשתפו את פרטי ההתחברות.
- נתוני התשלום באתר מיועדים להדגמה בלבד; אין להשתמש בהם לעיבוד תשלומים אמיתיים.
