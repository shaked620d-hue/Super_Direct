תכנון מסכים — צד לקוח

20 מסכים, כל אחד מסומן לפי מי שרואה אותו: אורח (לא מחובר), לקוח מחובר, או מנהל. עמודי ניהול חסומים בצד הלקוח ל־guardAdminOnly() וגם דורשים הרשאת אדמין מהשרת. שורות מודגשות הן מסכים שלא היו במסמך הקודם.

02

דרישות פונקציונליות — צד שרת

28 נקודות קצה (endpoints) ב־6 תחומים, כל אחת עם method, הרשאה נדרשת ומה היא מחזירה. הרשאות נאכפות בפועל ע"י JWT (authenticate) + בדיקת תפקיד (authorizeRoles). שורות מודגשות נוספו מאז המסמך הקודם.

03

ניהול מידע — קבצים ו־DB

MongoDB Atlas, 5 אוספים (collections). קשרי גומלין משלבים גם הפניה אמיתית (reference) וגם מזהה מספרי חופשי, לפי מה שהתאים לכל מקרה.

Customer

auth.model.js
  • firstName, lastNameString, חובה
  • emailString, חובה, ייחודי (unique)
  • passwordString, מוצפן ב־bcrypt דרך pre('save')
  • addressString, חובה
  • paymentMethodString, 4 ספרות, אופציונלי
  • roleenum: customer / admin

Product

product.model.js
  • name, descriptionString, חובה
  • price, stockNumber
  • categoryIdNumber, חובה — מפתח זר חופשי אל Category.id
  • imageString (נתיב קובץ תחת /public/products)
  • containsGluten/Dairy/Nuts/Eggs/SoyBoolean, ברירת מחדל false

Category

category.model.js
  • idNumber ייחודי, אוטו־אינקרמנט בקונטרולר
  • name, slug, descriptionString, חובה
  • eyebrow, intro, bannerAlt, productsTitleString, תוכן שיווקי אופציונלי
  • icon, imageString
  • soldByWeightBoolean — מחיר לק"ג מול ליחידה

Order

order.model.js
  • customerIdObjectId, ref: 'Customer'
  • items[]{ productId (ref: Product), name, price, qty, unit }
  • phone, deliveryFeeString / Number, חובה
  • orderDate, expectedDeliveryDate
  • totalPriceNumber, מחושב בשרת
  • statusenum: התקבלה / בהכנה / נשלחה / נמסרה

Message

message.model.js
  • name, email, subject, messageString, חובה
  • attachmentString (נתיב קובץ תחת /public/messages), אופציונלי
  • handledBoolean, ברירת מחדל false — הופך true גם אוטומטית כששולחים תגובה
  • timestampscreatedAt / updatedAt אוטומטיים

קשרי גומלין

  • Customer ← Order (קשר אמיתי, ObjectId ref)
  • Order → ORDER_ITEM (מכיל, מערך מוטבע)
  • Product ← ORDER_ITEM (מופיע ב)
  • Category ← Product (משויך אל, מזהה מספרי, לא ref)
  • Message - עצמאי, ללא קשר לשאר האוספים
💡 למה לא הכל reference: Order→Customer ו־Order.items→Product הם קשרים אמיתיים (ObjectId + ref + populate), כי צריך למשוך נתונים עדכניים מהאוסף המקושר. Product→Category הוא מזהה מספרי פשוט (לא ref) כי צד הלקוח היה זקוק למספר יציב וקריא לסינון URL עוד לפני שהיה קשר אמיתי — שילוב של שתי הגישות, כמו שהמסמך המקורי מרשה.
✅ מצב עדכני (11.10.2026): חמשת האוספים כולם ב־MongoDB Atlas אמיתי. מאז הגרסה הקודמת של המסמך נוספו: מחיקת קטגוריה בטרנזקציה אחת (מונעת מוצרים יתומים), ניקוי קובץ תמונה בעת מחיקת מוצר, שדה email ייחודי, ו־enum על סטטוס הזמנה.
